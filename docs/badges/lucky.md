# lucky 家族

代表色：`#FFD700`
家族定位：中文互联网 / 民俗语境下的数字玄学——基于 HEX 字符串中的吉祥数字文本模式，以及三通道上的吉祥常数。

> 📖 本家族的徽章表（含判定条件、命中数、概率 p 与 CP）见 [../BADGES.md](../BADGES.md) 的「### lucky — 玄学」一节。CP 与稀有度由全色域概率推导（`ep = 100 / p`），请勿手写。

## 备注

### 与 math / pattern 家族的区分（重要）
- `lucky-triple-six` / `lucky-triple-eight` 判定的是 **HEX 字符串的文本模式**：把 6 位十六进制数字连写后是否存在连续三个相同字符（允许跨字节边界），用定长 3 字符的**精确全等**比较实现（非正则、非模糊匹配）。math / pattern 家族判定的是数值性质（质数、2 的幂、等差、回文等），二者判定域不同：
  - `#006660`（R = 0，G = 102，B = 96）命中「六六大顺」，但其通道值没有任何等差数列结构；
  - 反例 `#010203`（R = 1，G = 2，B = 3）是典型等差数值，却完全不含任何连续如意数字。
- `lucky-sum-520` 用的是三通道和，但目标是**民俗吉祥常数 520**，而非 math 家族的「和是质数 / 平方数」等结构性性质。

### 反冗余（同家族内）
- 六条覆盖不同维度：文本三连（666 / 888）、末位字节（88）、通道和（520）、数字禁忌（无 4 且双 8）、精确通道三元组（正金）。两两均不构成蕴含：
  - 存在交集但不构成蕴含的例子：`#666888` 同时命中「六六大顺」与「八方来财」，但 `#006660` 只命中前者、`#008880` 只命中后者，互不为子集；`#488800` 命中「八方来财」却不命中「避四纳八」（含 4），说明后者不是前者的超集。
  - `lucky-tail-double-eight`（HEX 末两位为 88）只锁定末字节，`#008880`（B = 128）不命中，二者互不蕴含。
  - `lucky-golden-tone` 的 `#FFD700` 完全落在其余五条的判定集之外（无 6/8/4 文本模式、末两位 ≠ 88、和为 470）。
- 未写「三通道和为 888」：R + G + B 的理论最大值为 765，该条件恒不命中，属于不可实现的条件（规范第 5 节约束 5 要求 check 与 description 一致且真正可达），故改为可达的吉祥常数 520。

### 跨家族重叠说明
- 「金玉满堂」不是 culture 家族的精确色值比较，而是**三通道数值**的精确判定（`R = 255 且 G = 215 且 B = 0`），未使用任何 HEX 字符串匹配；描述中给出 `#FFD700` 仅为等价换算提示，故不侵占 culture 家族的特许例外。
- 本家族所有条件均为精确等值 / 计数判定，不含「近似」「模糊」匹配，符合规范第 5 节 check 约束 3。
- 与 `pattern` 家族：吉祥数字的**文本形态**天然带来通用模式巧合，属于跨家族（规范第 6 节仅「建议」遵守）的可接受重叠，已在测试中验证不含同族蕴含：
  - 连续 `666` / `888` / 末尾 `88` 都必然含一对相邻相同字符，故命中 `pattern-echo`；但 `pattern-echo` 覆盖面远大于本家族三条（如 `#AABBCC`、`#112233` 命中 echo 却不含任何吉祥三连），反向不成立。
  - `#FFD700`（金玉满堂）字节序 `FF > D7 > 00`，会同时命中 `pattern-descending` / `channel-descending`；这是单一色值的巧合，`lucky` 判定的是「是否恰为正金三通道」，与「字节是否递减」维度不同。
- 与 `math` 家族的边界见上节：`lucky` 只认特定的民俗常数（666 / 888 / 88 / 520 / 正金），不判定奇偶、质数、幂次、等差等结构性数值性质。
