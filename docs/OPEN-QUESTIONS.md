# 待裁决的问题（供外部讨论）

写这份文档是为了把**悬而未决的技术决策**连同完整背景交出去，让不了解这个项目的人（或另一个 AI）能独立判断。

## 这份文档怎么用

**约定：项目里所有有争议的决策都写在这里**，不留在线下讨论里。

每个问题按固定四段写：

```
【争议】        一句话说清争的是什么
【我的判断】    倾向怎么做 + 理由
【另一种合理做法】  反面是什么、代价在哪
【判据】        该用什么标准决定
```

**第四段最重要。**前两段只是我的立场——如果读的人只看到我的理由，这个讨论就没有意义。
**判断的标准必须是可观测的东西**（使用频率、维护成本、出错概率），不是"我觉得"。

**每条都要自带完整背景**，不假设读者读过这个仓库、或读过之前任何一轮对话。

**已决议的不留在这里。**决议后移到 `docs/resolved/`（该目录被 git 忽略）。
**本文档只放还没定的。**

## 下次往这里写什么

**不是所有技术选择都该进这份文档。**判据是：

| 该进 | 不该进 |
|---|---|
| 有两种合理做法、各有代价，需要人拍板 | 只有一种做法，或另一种明显更差 |
| 结论依赖**项目之外的判断**（产品取向、使用频率预期） | 纯技术事实问题，查一下就有答案 |
| 错了的代价**不能立刻看出来**（它可能很久以后才显现） | 错了当场就红，改回来很便宜 |

第 3 条尤其值得留意——**这个项目里真正伤人的从来不是"写错了"，
而是"写错了但所有测试都是绿的"**：

```
README 写 126 条徽章（实际 128）              人工发现
pricing.gen.ts 留下孤儿条目 extreme-404       人工发现，只差一步被提交
最稀有徽章被显示成「1 / 1 = 必然抽中」          人工审设计文档时发现
```

**没有一次是被测试发现的。**所以进这份文档的，应该主要是**测试看不见的那类决定**。
