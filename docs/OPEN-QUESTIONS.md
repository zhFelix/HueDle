# 待裁决的问题（供外部讨论）

写这份文档是为了把**悬而未决的技术决策**连同完整背景交出去，让不了解这个项目的人（或另一个 AI）能独立判断。

## 这份文档怎么用

**约定：项目里所有有争议的决策都写在这里**，不留在线下讨论里。

每个问题按固定四段写：

```
【争议】        一句话说清争的是什么
【我的判断】    倾向怎么做 + 理由
【另一种合理做法】  反面是什么、代价在哪
【判据】        该用什么标准决定
```

**第四段最重要。**前两段只是我的立场——如果读的人只看到我的理由，这个讨论就没有意义。
**判断的标准必须是可观测的东西**（使用频率、维护成本、出错概率），不是"我觉得"。

**每条都要自带完整背景**，不假设读者读过这个仓库、或读过之前任何一轮对话。

**已决议的不留在这里。**决议后移出本文档（归档在 `docs/resolved/`，该目录被 git 忽略）。
**本文档只放还没定的。**

## 一：定价表与徽章定义的 id 集合，要不要有一条断言？

### 背景（读这一条所需的最小上下文）

**HueDle** 是每日随机颜色收集游戏。徽章是判定函数 `check(color) => boolean`，用 TypeScript 写在
`packages/shared/src/badges/<family>.ts`（10 个家族文件，共 128 条）。

RGB 各 8 位 ⇒ 颜色空间**有限**（2²⁴ = 16,777,216 色），所以每条徽章的命中数 `hits` 可以**穷举出精确值**。
这些值存在**生成文件** `packages/shared/src/pricing.gen.ts` 里，由「枚举」步骤产出：

```
hits → p = hits / 2²⁴ → ep = 100 / p → rarity
```

**生成物与源码必须一致**——这是这套系统的核心不变量。

### 争议

**要不要加一条断言，强制 `pricing.gen.ts` 的 id 集合 == 徽章定义的 id 集合？**

### 已确认的事实

**2026-10-05 真的发生了污染。**一次真跑之后，工作区留下：

```
pricing.gen.ts       多了一行 'extreme-404': { hits: 1, ep: 1677721600, rarity: 'mythic' }
packages/shared/src/badges/     没有 extreme-404 的定义
docs/research/PRICING-CURRENT.md   写着「徽章条数：129」（实际 128）
```

即**孤儿定价条目**——生成物里有一条永远不会有对应徽章的记录。

**而当时所有测试都是绿的**（shared 177 / web 348 / admin 427）。
**没有任何断言覆盖「定价表里的 id 是否都有对应的徽章定义」。**

它是被我人工发现的，不是被测试发现的。**只差一步就被 `git add -A` 提交进历史。**

### 【我的判断】该加

两个方向都要查：

| 方向 | 含义 |
|---|---|
| 定价表有 id、徽章里没有 | **孤儿**（就是这次这种） |
| 徽章有 id、定价表里没有 | 缺定价数据——那正是「自举死锁」的成因（enumerate 需要定价 → 定价需要 enumerate） |

代价极小：一条 `expect(new Set(pricingIds)).toEqual(new Set(badgeIds))`。

### 【另一种合理做法】不加

- **枚举本来就会重新生成定价表**，所以孤儿在**下次枚举时自动消失**
- 孤儿是**无害的**：运行时没有人会去查一个不存在的徽章 id（`restoreScore` 之类只查存在的）
- 已有别的指标覆盖相邻问题：本地管理工具有一条 **M5「幽灵徽章 id」**，
  但那个查的是**数据库存档里有、代码里没有**（反方向），不是定价表

### 【判据】

**孤儿的存活时间是多久？**

- **下次枚举就没了** → 不必加断言
- **但它可能被提交** → 那就成了仓库历史的一部分，而且**所有测试照样绿**
  ——这正是这次离发生只差一步的情况

**具体要你判断的**：

> 一份**错误的生成物**在仓库里活着（测试全绿、CI 通过），这个代价，值不值得一条
> `toEqual` 的断言来防？

**相关的旁证**：这个项目里已经有过一次同类事故——
README 写着 126 条徽章（实际 128），**是人工发现并修的，不是测试发现的**。
项目后来确立了一条原则：**数字不写死，指向生成源或动态取值**。
